# How the app works

Notes for anyone changing the macOS app. The README covers using it.

## Layout

`app/CouncilCore` is a SwiftPM library with the logic that has nothing to do with SwiftUI: config parsing, the
chat log, session state, event normalization and launch plans, each with its own tests. `app/Council` is the
SwiftUI app. The split exists so the rules can be tested without a window.

The app reads `council.toml`, `chats/` and `runs/` exactly as the CLI writes them, and it never edits a chat's
`config.json`. Anything it needs to remember per session goes in an `app.json` beside it: CLI session ids, the
last message you saw, whether the chat was live.

```bash
app/build.sh                  # generate the Xcode project from app/project.yml and build Debug
app/build.sh test             # 250 CouncilCore tests, 51 app tests
app/build.sh run              # build and open Council.app
app/build.sh install [dir]    # build Release and install to /Applications, or a directory you name
app/build.sh snapshot chats/<dir> out.png [w h] [--dark] [--live] [--terminal <member>] [--chrome]
app/build.sh drive chats/<dir> "<message>" [--timeout s] [--to a,b] [--resume]
app/build.sh ask runs/<dir> [--timeout s] [--retry-moderator]
```

`Council.xcodeproj` is generated by xcodegen and gitignored, so every new source file needs a `build.sh` run
before Xcode knows about it.

## Members

Each member is a hidden SwiftTerm terminal running the real CLI, one per member, started from a chat's "Start
members" banner or by sending the first message. Each gets `COUNCIL_CHAT` and `COUNCIL_AS` in its environment,
so `council post` can't post as somebody else.

The CLIs report what they're doing through their own hook systems, which all call `council event`. That appends
to `events.jsonl` in the session folder, and the app tails that file to know when a member started, took the
prompt, ran a tool, finished, or needs a person. Hook payloads differ per CLI and are normalized in
`EventNormalizer`; kimi emits the Claude Code contract unchanged, down to the field names, so it's read with the
same code.

Clicking an agent in the sidebar shows its terminal. While the app is pasting into a terminal, keyboard input to
it is dropped, so a paste can't be interleaved with your typing.

Two members need setup the others don't:

- **Claude Code** gets a settings file merged with the app's hooks, passed with `--settings`.
- **Kimi Code** takes hooks only from the config file in its data directory, so each member gets a
  `KIMI_CODE_HOME` of its own under the chat: the user's config regenerated with council's hooks, credentials
  symlinked rather than copied, and the working folder's trust written in advance.

Every member is also told where the chat directory is (`--add-dir` for Claude Code and kimi, a writable root for
Codex). Without that, a member that isn't running unattended would have to ask permission before every single
reply, because answering means running `council post`, which writes to the chat directory and not to the folder
the member works in.

## Routing

Typing in the composer posts to `chat.jsonl` as `user` and starts the members if they aren't running. Who gets
prompted follows the CLI's rules: no mentions goes to everyone, `@name` goes to that member, a member's reply
goes to whoever it mentions, each hop spends one reply from the chat's budget, and "wrap it up" asks for final
positions and stops routing mentions.

Bursts within four seconds arrive as one delivery. A member is only prompted once it's idle, so nothing lands on
top of a turn in progress. When a message the whole council received has been answered by everyone, each member
is asked once to read the others and reply only if it has something to add. That reaction pass costs one reply
from the budget and is skipped while wrapping up.

Only one router may drive a chat at a time. The app takes `router.lock` in the session folder when members start
and drops it when they stop or the app quits. `council chat` and `council session` take the same lock, and each
refuses a chat the other holds, naming the holder. A lock whose process is gone gets taken over automatically.

## Verdict runs

⇧⌘N asks the council. Every member gets a hidden terminal, is pasted the prompt the CLI would have sent, and
answers with `council post`. The app writes each answer to `r<N>/<member>.md` with a `.done` record beside it,
then asks the moderator and saves `verdict.md` and `transcript.md`. That's the same directory `council runs`,
`council show` and a resumed `council ask` read.

A member that never answers is recorded as failed, and the moderator proceeds with what it has as long as two
members answered. Quitting mid-run offers Resume, which asks only for the missing answers. A moderator that gave
up offers Retry, which keeps every answer. The members' own bus, events and ledger live in a hidden `.app/`
folder inside the run, so the run directory holds only what the CLI would have put there.

Runs the app creates take only members it can host as terminals. An `openai` member's credentials live in
`council.toml` under keys the app doesn't model.

## Testing without spending quota

`COUNCIL_FAKE_MEMBERS=1` runs `app/Tools/fake-member.py` in place of every CLI. It's a scripted stand-in that
turns on bracketed paste, emits the same hook events and replies through `council post`, so the whole delivery
chain can be exercised for free. Its `FAKE_*` variables simulate slow starts, permission prompts, crashes,
silence, trust dialogs and "nothing to add". `FAKE_ONLY=<name>` applies them to one member and leaves the rest
normal.

```bash
app/Tools/integration/fake-member-flows.sh          # 22 scenarios, 75 checks, about 30 minutes
app/Tools/integration/fake-member-flows.sh crash deaf
```

Don't run `build.sh` while the suite is running. It regenerates the Xcode project the suite is building against.

The scenarios are where the delivery guarantees are actually tested: that every routed message ends in a reply,
a note or a card, that no delivery is left open, and that nothing the app sends ever answers a dialog on the
user's behalf.

## Start-up states that look like bugs

**A folder trust dialog.** Both Claude Code and Codex ask whether they trust a folder they haven't seen. The
member reads "needs attention" with a card naming the dialog, and you answer it in that member's terminal. The
app never answers one itself. It used to, by accident, because the briefing it pasted ended in the Return that
selected "Yes, continue", and there's a scenario in the suite specifically to keep that from coming back.

Codex takes a config override meant to pre-approve this, and the app passes it. It doesn't work: measured
against codex-cli 0.154.0 on a folder nothing had trusted, the dialog appears anyway, under both the old
unattended flags and the current asking ones. Trust does get inherited from a trusted parent folder, so a new
directory under one you've already approved starts clean.

**"starting…" for a few seconds.** Codex only reports its session with the first prompt, so the app declares it
ready once its screen has settled rather than waiting for an announcement that won't come.

## Signing

Signing is per-machine and deliberately not in the repo. Without `app/signing.local` the build is ad-hoc, which
builds and runs anywhere but hands the app a new identity on every build. macOS keys permission grants to the
signature, so you'll be asked again for Documents access after each rebuild, and anything the CLIs do through
AppleScript prompts again as "Council.app wants to control System Events", because they run as the app's
children. Copy `app/signing.local.example`, name your own Apple Development certificate and team, and it stops.
That file also explains the certificate chain problem that reports a perfectly good certificate as "0 valid
identities found".

The test host never touches the council folder, for the same reason.

## Design

Figtree throughout, bundled under the SIL Open Font License in `app/Resources/Fonts` and registered with
`ATSApplicationFontsPath`, so nothing needs installing. Only the terminal and fenced code stay monospaced.

The palette is indigo `#3D348B`, periwinkle `#7678ED`, amber `#F7B801`, orange `#F18701` and vermilion `#F35B04`,
on a `#0B0B0F` canvas in the dark.
